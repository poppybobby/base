# アプリ開発の引き継ぎ

この ZIP を開くと、フォルダの中ではなく、次のファイルが直下にあります。

- planner.js（21,759バイト。ルート計算）
- reader.js（4,828バイト。画像の文字認識）
- index.html（22,564バイト。画面の版 11）
- audit.html（18,321バイト）
- planner.test.js（11,544バイト）

`public/` は同じ一式です。`vendor/` に Tesseract と Leaflet があります。見本画像 `fixtures/flex-list.png` は春日市の番号9、10、11、12です。ピン1から46の鮮明な長尺は、この ZIP に入っていません。

GitHub の `main` にも同じ `planner.js` と `reader.js` があります。README だけを見て「JS が無い」と書かないでください。

この文は、当日の配達ルートアプリを引き継ぐための指示です。履歴を先に全部読み、そのあとで手を動かしてください。返答は日本語です。利用者をデバッガーにしません。画像を読み、位置を取り、GoogleマップのナビURLまで自分で通した事実だけを完成と呼びます。

## 利用者と製品

利用者は Amazon Flex の配達員です。毎日、市もルートも変わります。福岡に固定しません。

入力は次の4つだけです。

- 出発時刻
- 終了時刻
- その日の配達リストの長尺スクリーンショット
- 渋滞エリアの地名（例: 赤坂、警固）

出力は、その日の条件で運転時間が短い順のルートと、ワンタップで始まる Googleマップのナビです。

## 守る規則

- 日本の左側通行。距離が同じくらいなら左折を優先する。左折のためだけに迂回しない。
- 入力された渋滞エリアは先に回る。
- ナビURLは `https://www.google.com/maps/dir/?api=1&travelmode=driving&dir_action=navigate` を使う。`optimize=true` は付けない。最初の区間に `origin` は付けない。件数が多いときは10件区切りで、次の区間の起点は前の区間の終点にする。
- 朝7:00–9:00は通学の一方通行が多い。到着予定がその時間に入り、終了が9:00より後で締切にも余裕がある件は9:00以降に回す。終了が9:00前なら規制中でも届けて印を付ける。締切が9:00までに終わる件は先に回す。現地の標識がナビより優先。
- 集荷は原則として並びの1件目、持ち戻りは最後のステーション表記。読み取りが2件以下のときに両端を機械的に捨てると、実在の配達先（例: 福岡市博多区光丘町1丁目1）まで消える。市・区のある番地は残す。Logiport と、市の付かない江辻だけを拠点の行として外す。
- チャットの画像添付は、縦に長いスクリーンショットを長辺約1024pxまで潰す。横1080pxの長尺は横76pxになり、番地が消える。Googleファイルにある原本は鮮明。アプリのファイル選択でその原本を読む。横500px未満は、停留が無いと言わず、横幅を出して原本を選ぶよう伝える。

## いまのファイル

- リポジトリ: poppybobby/base の main
- この ZIP の index.html は「画面の版 11」
- 画面の版 11 は、配達先の位置が1件でも欠けるとナビを出さない
- 住所検索: 国土地理院 msearch.gsi.go.jp
- 文字認識: 同梱の Tesseract 日本語OCR
- https://daily-route.apps.grok.bot は、この ZIP を置いたあと更新していない。開くとログイン画面になる

県名だけの検索結果は都道府県の重心に落ちるので捨て、県名を外して再検索する。

## 履歴で繰り返してはいけないこと

- 「監査 24件合格」「監査 27件合格」は検査項目の数です。配達件数ではありません。
- 監査が最後まで通した画像は、春日市の4件（番号9、10、11、12）です。ピン1から46の当日リストではありません。
- 地図のスクリーンショットには博多区の番号ピンが写っていますが、番地がありません。その画像だけではルートは作れません。
- 46件分の長尺で、こちらが持っているのは横76pxまで潰れたJPEGです。番地は読めません。
- 本番では、46件に対してルートが35件になりました。35は、位置が取れた件だけを数えた数です。残りの11件はルートに入っていません。利用者はそこで「もう終了」と言っています。
- 江辻や Logiport で止まった、光丘町を消して「あいだの配達先が残っていません」と出た、監査がその失敗を合格にした、という経緯があります。同じ合格の出し方をしません。

## 完成の定義

ピン番号1から46の46件が写った鮮明な長尺を、アプリ自身が読み、46件から拠点の行を除いた配達先の位置を取り、その全件が GoogleマップのナビURLに入っていることです。

4件の見本、検査項目の件数、位置が取れた一部の件数を、46件の完成とは呼びません。鮮明な46件の長尺が入力に無いなら、無いと書き、ルートを作ったとは書きません。
